## 1. 推荐结构

根据任务删减或合并相邻部分，同时保持研究过程的先后顺序。

| 顺序 | 部分 | 主要内容 |
|---|---|---|
| 1 | 使用说明 | 运行顺序、预计耗时、输入和输出位置 |
| 2 | 研究目标与依据 | 研究问题、资料来源、方法范围和目标结果 |
| 3 | 数据清单 | 文件、字段、单位、时间范围、空间范围和数据版本 |
| 4 | 方法与参数 | 公式、统计方法、参数值、来源和必要假设 |
| 5 | 环境与路径 | 依赖、路径变量、输出目录和少量运行开关 |
| 6 | 数据读取与质检 | 类型转换、缺失、重复、异常、范围和单位检查 |
| 7 | 分步计算 | 按研究方法顺序计算，并就地展示中间结果 |
| 8 | 结果输出 | 表格、图片、诊断和文件保存 |
| 9 | 结果索引 | 结果名称、方法来源、代码步骤和输出位置 |
| 10 | 运行摘要 | 输入状态、假设、缓存、耗时、差异和未完成事项 |

## 2. 单元说明模板

在每个主要计算步骤前使用简洁的 Markdown 单元：

```markdown
## 第 N 步　步骤名称

**研究依据：** 章节、公式、文献、数据说明或用户设定
**本步输入：** 数据对象、文件、字段和单位
**执行内容：** 本步计算及其研究含义
**生成结果：** 变量、表格、图片或输出文件
**质量检查：** 范围、缺失、单位、数量或对照关系
**预计耗时：** 秒、分钟或较长时间
```

短步骤可以保留其中最相关的项目。说明应帮助读者理解研究过程，避免重复解释显而易见的 Python 语法。

## 3. 代码组织原则

- 在一个单元中完成一个容易描述的研究步骤。
- 将路径、常量和论文参数集中放在前部，并在旁边标注来源。
- 使用具有研究含义的变量名，例如 `monthly_flow`、`valid_years`、`trend_table`。
- 让数据转换、筛选和聚合步骤保持可见。
- 为重复公式、文件循环和独立统计方法编写小函数。
- 将辅助函数放在首次调用之前。
- 控制函数参数数量；可以直接读取的研究常量无需逐层传递。
- 根据任务规模决定类和多文件结构。优先采用读者能够顺着 Notebook 追踪的数据流。
- 依赖前置变量的单元可以在开头检查关键变量，并给出清楚的运行提示。

## 4. 数据与结果溯源

### 方法与参数登记

在 Notebook 前部建立一张简洁表格：

| 项目 | 数值或方法 | 来源 | 位置 | 备注 |
|---|---|---|---|---|
| 示例参数 | 用户填写 | 论文或说明 | 章节、公式或页码 | 单位和适用范围 |

“来源”可以是论文、补充材料、数据文档、标准、用户设定或明确标注的模型默认值。

### 数据处理记录

至少记录：

- 原始文件和数据版本；
- 读取的工作表、变量或字段；
- 筛选条件和研究范围；
- 缺测、重复和异常处理；
- 单位换算与坐标、时区或日历约定；
- 派生数据和缓存的生成位置。

### 结果索引

在末尾汇总：

| 结果 | 对应步骤 | 输入 | 方法依据 | 输出文件 | 状态 |
|---|---|---|---|---|---|

结果索引用于定位计算链路，无需重复保存全部数值。

## 5. 缓存与耗时步骤

- 为耗时循环显示处理数量、进度或阶段名称。
- 将缓存写入当前 Notebook 的独立输出目录。
- 在复用缓存时显示缓存路径、生成条件和时间范围。
- 保留从原始数据完整重建的路径。
- 当方法、参数或输入数据改变时，重新生成受影响的缓存。
- 使用少量含义明确的开关控制重建行为。

## 6. 图表显示与导出

- 在绘图步骤中同时显示图形并保存文件。
- 集中定义字体、负号、图幅、颜色、分辨率和背景。
- 使用用户指定的字体和输出格式。
- 保存前完成布局调整，保存后释放不再使用的图形对象。
- 检查标题、坐标轴、图例、单位和中文字符。
- 对比 Notebook 内嵌图和导出图。内嵌后端重新渲染导致差异时，可直接显示已保存文件：

```python
from IPython.display import Image, display

figure_file = FIGURE_DIR / "figure_name.png"
fig.savefig(figure_file, dpi=FIGURE_DPI, bbox_inches="tight")
plt.close(fig)
display(Image(filename=str(figure_file), width=900))
```
